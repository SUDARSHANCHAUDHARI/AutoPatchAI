# Contributing

This is a private SudarshanTechLabs project.

## Local Workflow

1. Create a short-lived feature branch from `main`.
2. Keep changes focused and small.
3. Add or update tests when behavior changes.
4. Run the available local checks before pushing.
5. Open a pull request with a clear summary and test notes.

## Commit Style

Use concise conventional-style messages when practical, for example:

- `feat: add log parser`
- `fix: handle empty scan results`
- `docs: update threat model`

## Safety

Never commit secrets, real credentials, local config, private keys, production logs, or signing material.
